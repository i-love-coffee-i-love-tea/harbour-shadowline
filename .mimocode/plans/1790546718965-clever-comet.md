# Maintainability Full Sweep — harbour-shadowline

## Goal
Improve maintainability of the QML/JS Sailfish OS globe app by: removing dead code, extracting data and DB logic into modules, decomposing large functions, eliminating duplication, centralizing constants, improving error handling, and modernizing JS.

## New files (3)

| File | Purpose |
|------|---------|
| `qml/js/constants.js` | Shared constants: DEG, DB params, rendering values, timer intervals, drag sensitivity |
| `qml/js/store.js` | Centralized DB layer: CRUD, settings (loadSetting/saveSetting), center position. Replaces 7 functions from MainPage + CoverPage's independent DB access |
| `qml/js/cities.js` | City data (cityTz dict + presetCities array, ~255 lines) extracted from LocationPicker.qml, plus `getTimezone()` and `filterCities()` helpers |

## Modified files (7)

### `qml/js/solar.js` — Modernize
- Import `DEG` from constants.js (remove local `var DEG`)
- `var` → `const`/`let` throughout

### `qml/js/projection.js` — Remove dead code, modernize
- Delete dead functions: `greatCircleInterpolate()` (34-68), `terminatorPoints()` (72-120), `julianDayApprox()` (122-131) — all unused, `terminatorPoints` also had dead `Qt.include("solar.js")` and duplicated solar calculations
- Import `DEG` from constants.js (remove local `var DEG`)
- `var` → `const` in surviving `project()` function
- **Result: 131 → ~30 lines**

### `qml/pages/MainPage.qml` — Remove god-object DB responsibilities
- Remove all 7 DB/settings functions (openDb, loadLocations, addLocation, removeLocation, loadCenterLongitude/Latitude, saveCenterLongitude/Latitude)
- Remove `property var db`
- Use `Store.loadLocations()`, `Store.addLocation()`, `Store.removeLocation()`, `Store.loadCenterLon()`, etc.
- Replace hardcoded values with `Const.*` references
- **Result: 276 → ~160 lines**

### `qml/components/GlobeCanvas.qml` — Decompose onPaint, eliminate duplication
- Split 210-line `onPaint` into 8 named helpers: `_drawOcean`, `_drawNightSide`, `_drawSegments`, `_drawSun`, `_drawLocationMarkers`, `_drawSelectedPin`, `_drawGlobeRing`, `_inverseProject`
- `_drawSegments()` eliminates the duplicated coastline/border rendering loops (lines 144-163 vs 165-184)
- Extract `_inverseProject()` to flatten night-scanline nesting from 4 levels to 2
- Replace all magic numbers with `Const.*` references
- **Result: onPaint 210 → ~25 lines, file stays ~300 lines but with clean decomposition**

### `qml/pages/LocationPicker.qml` — Extract data, add validation feedback
- Remove inline `cityTz` dict and `presetCities` array (255 lines) → import from `Cities`
- Remove unused `existingNames` property (dead code)
- Use `Cities.filterCities()` and `Cities.getTimezone()`
- Add `errorHighlight` on lat/lon fields for out-of-range coords (instead of silent return)
- **Result: 459 → ~210 lines**

### `qml/components/LocationListItem.qml` — Deduplicate, flatten, fix error handling
- Delete `_formatHM()` (duplicates `Solar.formatTime()`), replace call with `Solar.formatTime(data.solarNoon)`
- Add `console.warn` to silent `Intl.DateTimeFormat` catch
- Flatten `updateTimes()` with early returns (max nesting 6 → 3 levels)
- Extract `_computeNextChangeTime()` helper

### `qml/cover/CoverPage.qml` — Use store.js, remove duplicate DB access
- Replace `LocalStorage.openDatabaseSync(...)` with `Store.loadLocations()`
- Remove `import QtQuick.LocalStorage 2.0`
- Replace hardcoded timer/canvas values with `Const.*`
- Add `console.warn` to catch block

## Implementation order

## Risk mitigation

- **`LocalStorage` in `.pragma library`**: May not work in Qt 5.6 pragma context. Fallback: remove `.pragma library` from store.js and re-test (non-pragma JS runs in QML component scope where LocalStorage is available). This is the highest-risk item — verify at step 2.
- **Night-side rendering performance**: `_inverseProject()` adds a function call per pixel (~2,800 calls/frame). Should be negligible but verify no frame rate regression.
- **No test suite**: All verification is manual.
